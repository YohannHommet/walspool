Crash Safety & Recovery

Why In-Memory Buffers Drop Production Data

Standard language queues (Go channels, Python Queue, Node EventEmitter) hold uncommitted items in RAM. In Kubernetes and container environments, pods are regularly evicted, rescheduled, or terminated by the kernel on memory pressure.

Walspool writes synchronously or group-commits every record to an append-only disk segment with an IEEE CRC32 checksum in its 29-byte binary header. Upon process crash or sudden reboot, Walspool scans segment boundaries, detects any incomplete tail writes, cleanly truncates corrupted bytes, and resumes draining without human intervention.

Operational Simplicity

Local Isolation & Zero Cluster Overhead

Centralized message brokers like Kafka excel at cross-service event streaming, but routing transient local retries and node telemetry through remote clusters introduces extra network hops, auth handshakes, and operational complexity.

Walspool operates right alongside your service as an in-process library or companion container. It secures burst traffic on local NVMe, protecting downstream brokers from spikes and freeing your network from transient chatter with zero cluster maintenance.

Architectural Blueprint

Dual-Engine Core & Multi-Segment Storage

Two specialized engines work in tandem behind strict Ports & Adapters boundaries: durable multi-segment NVMe storage and an ultra-fast in-memory streaming hub.

STORAGE ENGINE (WAL) 1,000,000+ ops/s

Multi-Segment Rotation & Auto-Pruning

High-throughput sequential write-ahead logging with bounded disk quotas. Automatically rotates active WAL files into immutable segments and guarantees zero-overhead pruning of fully acknowledged records as checkpoints advance.

▪
Deterministic Segment Rotation: Sealed at configurable size (`MaxSegmentSize = 64MB`) without blocking ingestion.
▪
Checkpoint Auto-Pruning: Unlinks fully committed segments on `Commit(offset)`, preserving NVMe storage.
▪
Segmented Crash Recovery: Discovers all segments in sequence and repairs torn tail writes with `os.Truncate`.
▪
IEEE CRC32 Protection: 29-byte binary header verifies integrity on every record boundary.

Integration

Client Libraries & Deployments

// 1. Import pure Go module (0 external dependencies)
import "github.com/YohannHommet/walspool"

// 2. Initialize persistent storage with 64MB multi-segment rotation
storage, _ := walspool.NewFileStorageEngineWithOptions("./data/spool", 50000, walspool.FileStorageOptions{
    MaxSegmentSize: 64 * 1024 * 1024,
})
hub := walspool.NewMemoryLogHub(50000)

// 3. Wire Spooler with In-Memory Observer
cfg := walspool.DefaultConfig()
spool, _ := walspool.New(cfg, storage, sink, nil, walspool.WithObserver(hub))
defer spool.Close()

// 4. Ultra-fast append (< 1 µs) - persisted to NVMe & indexed immediately
_ = spool.Enqueue(ctx, "orders.checkout", []byte(`{"trace_id":"tr-9941","total":149.00}`))

// 5. Query historical logs in < 15µs
logs := hub.Query(walspool.LogQuery{TraceID: "tr-9941", Limit: 10})
